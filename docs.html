Quick start

Requires Node.js 20+. Torrentor is a plain Electron app — no service, no account, no telemetry.

git clone https://github.com/sargeraas84/torrentor.git && cd torrentor
npm install
npm start

The test suite

npm run test:electron8 IPC checks through the real main process — search, favorites, health round-trip.
npm run test:ui25-step real-window playtest: types real queries, pages, favorites, VPN save & check IP.

Searching works out of the box: type ubuntu, blender open movie or moby dick audiobook and hit enter. With zero network, the Demo engine still shows the full flow (every Demo card is labeled).

Adding sources

Every engine lives in indexers/. The registry (indexers/registry.js) is the allowlist — the app never loads search plugins from the network, and no engine can bypass the proxy-aware network client.

An adapter is one file. The contract: search(query, ctx) returns normalized results, where ctx.network is the proxy-bound client:

// indexers/my-source.js
const { normalizeResult } = require('./base');
const ENGINE = { id: 'my-source', name: 'My Source', tagline: '…', kind: 'community' };

async function search(query, ctx) {
  const data = await ctx.network.getJson(
    'https://my-index.example/api?q=' + encodeURIComponent(query),
    { timeoutMs: ctx.timeoutMs, signal: ctx.signal }
  );
  return data.items.map((it) =>
    normalizeResult({
      itemId: it.id, title: it.name, infohash: it.infoHash,
      sizeBytes: it.size, seeders: it.seeders, pageUrl: it.url,
    }, ENGINE)
  );
}
module.exports = { engine: ENGINE, search };

Then register it in indexers/registry.js. If the source is real and probe-able, add a known-good probe term so the engine-health self-test covers it.

You own the decision. Review the source's terms, rate limits and content policy before adding it. Torrentor ships legal-friendly sources by default; adding an index is a deliberate operator choice.

VPN & proxy config

Torrentor doesn't bundle or sell a VPN. It makes any VPN you already run enforceable for search traffic: every outbound engine request goes through your route, and the exit-IP check is the source of truth.

Supported proxy types

TypeUse for
socks5Recommended — Tor, ssh -D 1080, WireGuard/OpenVPN apps exposing a local SOCKS port.
socks4Legacy SOCKS proxies.
httpHTTP CONNECT proxies; credentials supported.
  1. Run your VPN

    Any client that exposes a local proxy port — Tailscale, OpenVPN, Tor Browser, ssh -D.

  2. Save & check IP

    Settings → VPN & privacy → enter host/port → Save & check IP. The app shows the exit address the world sees.

  3. Verify

    If the exit IP matches your VPN's country/city, the route is live for all engines.

Honest limits. The proxy covers Torrentor's search traffic only — file downloads happen in your torrent client and follow its settings. The app can't detect your VPN by itself; only the exit-IP check proves it.

Engine health

Settings → Search sources runs a self-test: each real engine executes a known-good probe query through the same proxy-bound path a real search uses. Healthy means the probe returned ≥ 1 result — zero results is reported as failing, never as a silent green chip.

EngineProbe
Internet Archivebig buck bunny
Linux releasesubuntu 24.04 — this probe caught the releases.ubuntu.com redesign
Arch Linuxarchlinux
Demoexcluded — offline by design, always “available”

Verdicts (ok/count/latency/error) persist locally, so dots paint instantly on revisit. Health is informational: a failing source isn't auto-disabled — you can see it's dead before enabling it.

Changelog

What changed, release by release. Full notes always live on GitHub Releases ↗.

v1.1.0 — “Open culture”

2026-09-04 · release ↗

  • Portable Windows build — Torrentor-Setup-1.1.0.exe attached to the release; no install needed.
  • Open-culture browsing — Archive items now carry creator, year and their poster on cards; the idle screen gains an “Explore open culture” tile row; Archive-native mediatype chips (Movies · Audio · Texts · Software) filter the real classification.
  • Engine health self-test — Settings → Search sources probes every real source with a known-good query. A source that returns zero results is reported as failing, never as a silent green chip. This also surfaced and fixed a caching bug that made the Ubuntu probe flaky.
  • This website — landing page + docs, live at sargeraas84.github.io/torrentor.

v1.0.0 — Initial release

2026-09-04 · baseline

  • Meta-search across Internet Archive, official Ubuntu / Debian and Arch Linux releases, plus an offline Demo engine so the app works with zero network.
  • Parallel fan-out with a per-engine watchdog, infohash dedupe, and honesty ordering — real results before demo, relevance before size.
  • Favorites & history, result paging, thumbnails, and a VPN / proxy route with exit-IP check.
Shipped by hand, verified by machine. v1.1.0 was built and attached locally; every release runs the full suite — 49 Node checks, 8 Electron IPC checks, and a 25-step real-window playtest.
