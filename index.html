The idea in plain words

What is Torrentor, really?

A torrent isn't a file sitting on a server. It's a tiny recipe that tells your torrent client where to find the people sharing a file right now — and the magic is that those people are regular users like you, not a company. That's the “peer to peer” part.

Torrentor is a search engine for those recipes. Type one query and it asks a handful of trusted libraries at once — Internet Archive, official Ubuntu & Debian releases, Arch Linux, and more — then merges everything into one clean list of results, ranked by how well they match.

Most torrent search engines point you at whatever is being shared, with no idea where it came from or whether it can be trusted. Torrentor only searches sources that publish torrents on purpose — so every card is a real file with a real size, from a source you can name.

It doesn't download anything itself, and it doesn't hide behind an account or track you. Torrentor finds the recipe; your torrent client does the downloading, over the peer-to-peer network, with no central server in the middle.

Three things to know

  1. It's a catalog, not a downloader

    Torrentor finds the recipe (the .torrent or magnet link). Your torrent client — qBittorrent, Transmission, anything — does the actual downloading.

  2. One query, many libraries

    Search ubuntu and you get the official Ubuntu ISO torrents, Archive copies of Ubuntu magazines, and more — merged, deduped, relevance first.

  3. Honest by design

    No scraped pirate indexes, no fabricated results, no sponsored cards. If a result doesn't genuinely match your query, you won't see it.

Still fuzzy? Think of Torrentor as a library card catalog that can search several libraries at once — except instead of books, it's looking for the keys that unlock files being shared peer to peer, legally, right now.

One query runs against every enabled source at once. Cards appear the moment each source answers — not after the slowest one finishes — and a watchdog guarantees no engine can hang a run.

Smart merge

Duplicates across sources collapse into one card with an “also on …” badge. Ordering rules keep real results above demo fixtures, and relevance before size.

Rich cards

Category, size, seeders/leechers, age, infohash preview, source badges — and Archive items show creator, year and their poster.

VPN / proxy route

Every outbound search request goes through your own VPN or proxy — HTTP, SOCKS4/5, auth — with a one-click exit-IP check. Enforced in main, not the page.

Source health

A self-test probes every real source with a known-good query. Silent regressions — site redesigns that return zero results — show up as red dots, never green chips.

Open-culture browse

An idle “Explore open culture” row — public-domain films, old-time radio, LibriVox, silent cinema, 78rpm, NASA imagery — fires the same honest search, with Archive mediatype chips (Movies · Audio · Texts · Software) that filter the real classification.

VPN & privacy

Your VPN, enforced — not bundled

Torrentor deliberately doesn't sell you a VPN. Instead it makes any VPN you already run enforceable for search traffic, and proves it with an exit-IP check.

  1. Run any VPN or local proxy

    WireGuard / OpenVPN / Tailscale apps, Tor (socks5://127.0.0.1:9050), or ssh -D 1080 — all work.

  2. Point Torrentor at it

    Settings → VPN & privacy → pick the proxy type, enter host/port (and credentials if needed), hit Save & check IP.

  3. Confirm the exit address

    The IP check shows the address the world sees, so you can verify the VPN is actually on — the source of truth, since the app can't detect your VPN by itself.

Honest notes. The proxy applies to Torrentor's own search traffic. Actual file downloads happen in your torrent client, whose network settings govern them.

What “routed” means here

Every outbound engine request — Archive.org API calls, Ubuntu release pages, Arch feeds, IP checks — flows through the route you configured, from a single network module in the main process. Nothing in the page ever touches the network directly, so no engine can bypass the route.

Get Torrentor

Windows & macOS.
Built from source in seconds.

Requires Node.js 20+. The 1.2 release ships a Windows installer and portable .exe, plus a universal macOS .dmg — or three commands get you a running app from source.

git clone https://github.com/sargeraas84/torrentor.git
cd torrentor && npm install && npm start
npm run dist  # → portable Torrentor.exe
Why source-first? Torrentor is open source on GitHub — no installer you can't inspect, no telemetry, no accounts. The 1.2 release ships prebuilt installers for Windows (installer + portable .exe) and macOS (universal .dmg); npm run dist produces the same locally. macOS builds are unsigned, so the first launch is right-click → Open — normal for open-source apps.
